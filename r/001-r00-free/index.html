打开方式：双击 index.html，用 Chrome 打开。不用服务器，也不联网。

你最在意的那条：美术方案和技能都写进了方案

核心切片设计.md 第一节就是这件事，写了三点：

  • 美术用 design.md 已拍板的方案：分零件生成 + 代码拼装 + 零件分层动画（hi-bit 路线）。这一条比「美术全部用代码画、不用外部生图工具」优先。
  • 出图、处理、拼装、动画都走 pixel-character-design 技能的 hi-bit 路线：出零件用技能里的 gen-parts.sh 和 codex-imagegen，拼装用 hibit-kit.js，构建和截图用 hibit_build.py。
  • 这一轮读不到技能本体，所以直接用 美术/ 里按方案做好的东西：零件、原样的 hibit-kit.js，以及从技能的构建页和运行页改出来的 tools/build.html 和 game/art.js。

美术的具体做法：

  • 每个场景都从源图直接缩到 640×360 的像素格，每个场景一套色板（大部分 96 色，副本 64 色）。
  • 自动拼装：船首像按轮廓贴到船头，货堆和炮按脚下那段船舷的高度放，绳子从气囊的铜环拉到甲板。
  • 动画全靠零件分层，每秒 12 帧：螺旋桨 4 帧压扁转动、气囊比船身慢半拍浮动、甲板货一层层堆高、热度火光、被击中闪白。
  • 重建全部美术只要一条命令：node tools/build.mjs，约 4 秒，无头运行。

切片里能玩到的一整圈

  1. 开场 60 秒：被海盗追，按 Q 扔货，进港「冒尖而归」，木筏散架。
  2. 船坞：在侧面图上把模块一块块装回去，升力、推重比、速度档、甲板能堆几箱当场变化，有出航检查。
  3. 大地图：出航到城镇进货。第一箱一上船，速度档就从「快」掉到「中」，船身一沉，配一声闷响。热度到了会被盯上：可以扔货拖时间、钻进安全圈，或被追上时二选一（开战 / 认栽）。
  4. 副本：打海盗巡逻船，进竖版射击，自动开火，有冲刺、技能和擦弹充能。被打中时甲板上的箱子会飞出去，敌船的货也要飞过去接；打完是战后面板。
  5. 回家：货箱一箱箱滚进仓库，打上满舱 / 冒尖标。
  6. 夜市：摆摊、敲铃开市，客人带耐心条，船长去摊位拿货（一次最多两单）、回柜台递，有小费。还有大客户订单，打烊时口碑拆开写。然后进入第二天。
  7. 另外做了：造驮兽货船（甲板能堆 6–8 箱），以及被击落 → 留 1 件 → 沉货点 → 打跑守货的海盗 → 打捞。

测试情况

所有测试都在无头 Chrome 里跑，不弹窗口：

  • 从标题一路自动玩到第二天早上，没有报错。真实画面存了 18 张，在 截图/。
  • 被追、被击落、订单、驮兽、热度这几条流程分别单独跑过。
  • 七个场景各乱按 120 次，0 个运行时错误。

主要假设（不问你，都写在 notes.md）

  • 范围：只做木筏和驮兽两种底模、7 种模块。据点、首领、乱流、迷雾、海上事件、招牌货、伙计、建造模式、多人都留到后面。
  • 压缩的数：地图航程压到设计的约 1/4–1/3，被盯上的平均间隔压到 1/4，好让 10 分钟内就能碰到追逐。
  • 自己定的：连发炮的技能 design.md 没写，我定成「铜雨」；冲刺的参数也是我定的。
  • 平台：这一段只做了网页版，Windows 和 macOS 打包放到后面。联机还没做，但改状态的操作都写成了改一个 JSON 存档的纯函数，以后可以直接当主机权威的指令用。
  • 没往网上推：没建远程仓库，也没部署。
